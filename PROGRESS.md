# Прогресс подготовки

Документ намеренно не угадывает уже изученное. На первой диагностической неделе брат выставляет исходный уровень по фактическим решениям, после чего карта показывает готовность по каждой теме.

## Уровни освоения

| Уровень | Что означает      | Проверяемое основание                                                             |
| ------: | ----------------- | --------------------------------------------------------------------------------- |
|     `0` | Не проверено      | По теме ещё не было диагностики                                                   |
|     `1` | Узнаёт тему       | Понимает признаки, ограничения и сложность; после изучения решает `L`             |
|     `2` | Умеет применять   | Самостоятельно решает задачи `R` и пишет базовую реализацию на Java               |
|     `3` | Готов к олимпиаде | Решает `F` без подсказок, не раскрывая паттерн, и в установленное время           |
|     `4` | Навык закреплён   | Через 7–14 дней решает новую задачу темы либо применяет тему в смешанном контесте |

Просмотр теории или разбора сам по себе уровень не повышает. Одна неудачная задача тоже не понижает его автоматически: для понижения нужны две независимые проверки, показавшие одну и ту же проблему.

Для ролей `D/F/X` колонка «Что тренирует» в [`PRACTICE.md`](PRACTICE.md) скрыта намеренно. Раскрытие считается
подсказкой: оно не делает попытку бесполезной, но такая попытка не подтверждает уровень `3`. После разбора задачу
нужно решить заново, а затем проверить перенос навыка на новой задаче или через 7–14 дней.

Уровень `3` сам по себе образует очередь повторения. Каждую неделю из таких тем выбираются 2–3 темы: сначала приоритет `A`, затем темы, которые дольше не встречались в практике. Отдельный календарь повторений вести не нужно.

## Целевые уровни

К началу отборов:

- темы `A0/A1` — преимущественно уровень `3`, ключевые темы постепенно закрепляются на `4`;
- темы `B` — уровень `1–2`;
- темы `C` допустимо оставить на `0`, если они не нужны для конкретной олимпиады.

После прохождения отборов:

- темы `A0/A1` закрепляются на уровне `4`;
- темы `B` поднимаются до `3`;
- выбранные под конкретные финалы темы `C` поднимаются до `2–3`.

## Метрики, которые действительно важны

1. Доля задач, решённых без подсказки.
2. Время от чтения до правильной модели, отдельно от времени кодирования.
3. Доля контестов с завершённым upsolve.
4. Число повторяющихся ошибок одного класса.
5. Успех повторного решения через 7–14 дней.
6. Стабильность Java-шаблонов под временем.

Общее число accepted полезно только вместе с этими метриками.
