# Заметки

Это короткий журнал полезных выводов из задач и контестов. Он ведётся как хронологический поток: новая запись добавляется в конец файла, без таблиц и обязательных полей.

## Как пользоваться

1. Не писать заметку после каждой задачи. Если решение не дало нового переносимого вывода, записывать нечего.
2. Одной полезной мысли обычно достаточно одной строки.
3. Указывать номер темы как `T01`–`T34`. Номера совпадают в [`ROADMAP.md`](ROADMAP.md), [`PRACTICE.md`](PRACTICE.md) и [`PROGRESS.md`](PROGRESS.md).
4. Указывать задачу, если вывод связан с ней. Благодаря этому записи можно найти поиском по теме, номеру задачи или слову `Java`.
5. Не пересказывать всё решение. Записывать то, что действительно стоит вспомнить перед следующей похожей задачей или контестом.
6. Не копировать готовый текст из колонки «Что тренирует». Заметка имеет смысл только тогда, когда формулирует
   собственный новый признак, инвариант, ошибку или деталь реализации, обнаруженные во время решения.

Стоит сохранить:

- признак, по которому можно распознать алгоритм;
- ключевой инвариант или нетривиальную идею;
- повторяющуюся ошибку и способ её предотвратить;
- важную деталь доказательства;
- ловушку реализации на Java;
- полезный вывод о стратегии контеста.

## Пример

```markdown
## 24 июля 2026

- `T08` · CF 1742E — массив максимумов префикса монотонен: по нему можно сделать binary search, а ответ взять из массива префиксных сумм.
- `T18` · CF 1234D — для запросов различных букв достаточно отдельного Fenwick для каждой буквы.
- `T15` · CF 20C — Java: расстояния хранить в `long`, а устаревшие записи пропускать при извлечении из `PriorityQueue`.
```

Формат примера не является формой для обязательного заполнения. Запись может быть короче, если смысл остаётся понятен.
