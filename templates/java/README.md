# Java-шаблоны

Это не готовый `Main.java`, а проверенные строительные блоки для олимпиадных
решений. Шаблон нужно выбирать по операциям из условия, а не по знакомому
названию структуры.

Подробная теория и порядок изучения находятся в
[`ROADMAP.md`](../../ROADMAP.md), реальные наблюдения по олимпиадам — в
[`research.md`](../../research.md), задачи для закрепления — в
[`PRACTICE.md`](../../PRACTICE.md).

## Как применять файлы

На большинстве платформ решение отправляется одним файлом `Main.java`.
Поэтому есть два нормальных способа использовать шаблон.

1. Скопировать нужный класс в `Main.java` и убрать у него модификатор `public`.
2. Сделать его вложенным `static`-классом внутри `Main`.

Не нужно копировать весь каталог в каждое решение. Например, для задачи на
связность обычно достаточно `FastScanner`, `DSU` и кода самой задачи.

Перед использованием:

1. выписать требуемые **изменения** и **запросы**;
2. проверить, статичны ли данные и нужны ли откаты;
3. выбрать структуру по таблице ниже;
4. сверить индексацию и семантику диапазона;
5. адаптировать агрегат, если конкретный шаблон поддерживает не ту операцию;
6. протестировать `n = 1`, пустой диапазон, границы и максимальные значения.

Во всех диапазонных шаблонах этого каталога используются нулевые индексы и
полуинтервалы `[left, right)`.

## Быстрый выбор структуры

| Ситуация                       | Изменения           | Запрос                       | Структура                               | Сложность                                       |
| ------------------------------ | ------------------- | ---------------------------- | --------------------------------------- | ----------------------------------------------- |
| Компоненты только объединяются | `union(a,b)`        | связность, размер компоненты | [`DSU`](DSU.java)                       | почти `O(1)` амортизированно                    |
| Объединения нужно отменять     | `union` + откат     | связность в текущей версии   | [`RollbackDSU`](RollbackDSU.java)       | `O(log n)` на объединение, `O(1)` на один откат |
| Меняются отдельные элементы    | прибавить в точке   | сумма префикса/отрезка       | [`Fenwick`](Fenwick.java)               | `O(log n)`                                      |
| Меняются отдельные элементы    | присвоить в точке   | сумма отрезка                | [`SegmentTree`](SegmentTree.java)       | `O(log n)`                                      |
| Прибавление на целом диапазоне | `add(left,right,x)` | минимум диапазона            | [`LazyMinTree`](LazyMinTree.java)       | `O(log n)`                                      |
| Массив вообще не меняется      | нет                 | минимум диапазона            | [`SparseTableMin`](SparseTableMin.java) | подготовка `O(n log n)`, запрос `O(1)`          |

Если массив статичен и нужны только суммы, обычные prefix sums проще sparse
table. Если нужны другие операции — `max`, `gcd`, матрица, скобочная
информация, максимум с количеством — текущие segment/sparse-шаблоны нужно
адаптировать.

## DSU

Файл: [`DSU.java`](DSU.java).

### Для чего нужна

DSU, или система непересекающихся множеств, хранит разбиение объектов на
компоненты. Она быстро отвечает на вопросы:

- находятся ли две вершины в одной компоненте;
- что произойдёт, если добавить новое ребро;
- удалось ли ребру соединить две ранее разные компоненты;
- каков размер компоненты;
- сколько компонент осталось.

Типичные применения: алгоритм Краскала, офлайн-добавление рёбер, проверка
связности, объединение равных объектов и обработка компонент по возрастанию
веса или времени.

### Как распознать

- рёбра или связи только **добавляются**, но не удаляются;
- важна компонента, а внутреннее устройство пути не важно;
- запрос формулируется как «уже соединены?» или «объединить группы»;
- рёбра рассматриваются по весу — частый сигнал Краскала;
- нужно пропускать уже обработанные позиции через DSU-next.

### API и сложность

| Метод              | Смысл                                           |                    Сложность |
| ------------------ | ----------------------------------------------- | ---------------------------: |
| `new DSU(n)`       | создать `n` одноэлементных компонент            |                       `O(n)` |
| `find(v)`          | получить представителя компоненты               | почти `O(1)` амортизированно |
| `union(a,b)`       | объединить; вернуть `false`, если уже соединены | почти `O(1)` амортизированно |
| `componentSize(v)` | размер компоненты вершины `v`                   |                 почти `O(1)` |
| `components()`     | текущее число компонент                         |                       `O(1)` |

Оценка получается благодаря union by size и path compression.

### Как применять

Например, проверить, образуют ли данные рёбра связный граф:

```java
DSU dsu = new DSU(n);

for (int i = 0; i < m; i++) {
    int a = fs.nextInt() - 1;
    int b = fs.nextInt() - 1;
    dsu.union(a, b);
}

boolean connected = dsu.components() == 1;
```

В алгоритме Краскала значение `true` означает, что ребро действительно нужно
добавить в остов:

```java
if (dsu.union(edge.from(), edge.to())) {
    mstWeight += edge.weight();
}
```

### Где применялась

- ИОИП 2023/24, «Фрирен и интересные вопросы» — DSU;
- Всесибирская олимпиада 2022/23, «Робот-строитель» — DSU вместе с `gcd` и
  циклами перестановки;
- Innopolis Open 2025/26, «Хомячья зрелищность» — DSU-next как один из
  возможных инструментов обработки ещё не удалённых позиций.

### Ограничения

Обычная DSU не умеет эффективно удалять рёбра и возвращаться к старым
состояниям. Path compression меняет сразу много родителей, поэтому для
откатов нужен отдельный [`RollbackDSU`](RollbackDSU.java).

## RollbackDSU

Файл: [`RollbackDSU.java`](RollbackDSU.java).

### Для чего нужна

Rollback DSU поддерживает те же объединения компонент, но позволяет сохранить
номер версии и позднее отменить все изменения после неё. Она нужна для:

- DFS по дереву версий или состояний;
- divide-and-conquer по времени;
- segment tree по времени жизни рёбер;
- офлайн-динамической связности, где рёбра добавляются и удаляются.

Структура не использует path compression: без этого невозможно дёшево и точно
восстановить изменённых родителей.

### Как распознать

- после обработки ветки рекурсии состояние должно стать прежним;
- запросы образуют дерево версий;
- ребро активно только на некотором интервале времени;
- нужно отвечать о связности после добавлений **и удалений**, но все запросы
  известны заранее;
- в решении естественно звучит «сделать изменения → обработать детей →
  откатить».

### API и сложность

| Метод                | Смысл                              |                   Сложность |
| -------------------- | ---------------------------------- | --------------------------: |
| `new RollbackDSU(n)` | начальное разбиение                |                      `O(n)` |
| `find(v)`            | представитель без path compression |                  `O(log n)` |
| `union(a,b)`         | объединение с записью изменения    |                  `O(log n)` |
| `snapshot()`         | номер текущей версии               |                      `O(1)` |
| `rollback(version)`  | отменить изменения после версии    | `O(число отменённых union)` |
| `components()`       | число компонент                    |                      `O(1)` |

### Как применять

Главный шаблон — сохранить версию перед входом в ветку и гарантированно
откатиться после неё:

```java
void dfs(int v, RollbackDSU dsu) {
    int version = dsu.snapshot();

    for (Edge edge : edgesAddedAt[v]) {
        dsu.union(edge.from(), edge.to());
    }

    answer[v] = dsu.components();
    for (int child : children[v]) {
        dfs(child, dsu);
    }

    dsu.rollback(version);
}
```

Если `union` получает уже соединённые вершины, история не меняется. Откат к
сохранённому `snapshot` всё равно корректен.

### Где применялась

- Innopolis Open 2025/26, «Шустрик и коробки» — rollback DSU вместе с DFS по
  дереву состояний.

Сам приём динамической связности также относится к продвинутому слою
[темы 31 roadmap](../../ROADMAP.md#тема-31).

### Ограничения

- Нельзя добавлять path compression в `find`.
- Это офлайн-инструмент: для полностью онлайн-удалений нужна другая модель.
- Сам rollback DSU не знает время жизни ребра; интервалы обычно раскладывает
  отдельный segment tree по времени.

## Fenwick

Файл: [`Fenwick.java`](Fenwick.java).

### Для чего нужна

Дерево Фенвика — компактная структура для точечных прибавлений и сумм на
префиксе. Через разность двух префиксов оно даёт сумму любого отрезка.

Кроме обычных сумм, Fenwick часто используется как массив частот:

- подсчёт инверсий;
- число элементов меньше заданного;
- порядковая статистика;
- DP, где нужно брать лучший/суммарный ответ на префиксе координат;
- sweep line после сжатия координат.

### Как распознать

- есть много точечных изменений и запросов суммы на диапазоне;
- запрос всегда сводится к префиксу;
- элементы или координаты можно сжать;
- нужно считать, сколько ранее встреченных значений меньше/больше текущего;
- нужна позиция `k`-го активного элемента по накопленной частоте.

### API и сложность

| Метод                  | Смысл                                          |  Сложность |
| ---------------------- | ---------------------------------------------- | ---------: |
| `new Fenwick(n)`       | создать нулевой массив длины `n`               |     `O(n)` |
| `add(index,delta)`     | прибавить в одной точке                        | `O(log n)` |
| `prefixSum(right)`     | сумма `[0,right)`                              | `O(log n)` |
| `rangeSum(left,right)` | сумма `[left,right)`                           | `O(log n)` |
| `lowerBound(target)`   | первая позиция с накопленной суммой ≥ `target` | `O(log n)` |

`lowerBound` корректен, только когда накопленные суммы монотонны — например,
в Fenwick лежат неотрицательные частоты — и `target > 0`.

### Как применять

Построение по исходному массиву и запрос суммы:

```java
Fenwick fenwick = new Fenwick(n);
for (int i = 0; i < n; i++) {
    fenwick.add(i, a[i]);
}

fenwick.add(index, delta);
long sum = fenwick.rangeSum(left, right); // [left, right)
```

Поиск нулевого индекса `k`-го присутствующего элемента:

```java
int index = fenwick.lowerBound(k); // частоты должны быть неотрицательными
```

### Где применялась

- Московская олимпиада 2025/26, «Трудоголики» — DP + Fenwick;
- Всесибирская олимпиада 2024/25, «Эксперимент» — Fenwick как один из
  официальных подходов;
- Всесибирская олимпиада 2025/26, «Совет Четырёх Башен» — Fenwick вместе с
  two-pointer merge.

### Ограничения

Текущий файл поддерживает именно суммы. Для `min` на префиксе возможна
специальная версия Fenwick, но она имеет другие ограничения. Для произвольных
отрезков и сложных агрегатов обычно проще использовать segment tree.

## SegmentTree

Файл: [`SegmentTree.java`](SegmentTree.java).

### Для чего нужна

Дерево отрезков хранит агрегат для каждого сегмента массива и объединяет
соседние сегменты функцией `merge`. Оно полезно, когда данные меняются, а
запрос нельзя удобно выразить только через префикс.

Текущая реализация — простой итеративный вариант:

- присвоение нового значения одной позиции;
- сумма на полуинтервале `[left,right)`.

Та же структура после изменения `merge`, типа узла и нейтрального элемента
может хранить `min`, `max`, `gcd`, матрицы, хеши, скобочные подпоследовательности
и составные статистики.

### Как распознать

- обновления и запросы перемешаны;
- ответ для отрезка можно получить объединением ответов его частей;
- Fenwick недостаточно, потому что операция не является обычной суммой;
- нужен первый индекс, на котором агрегат удовлетворяет условию;
- в условии есть запросы на поддеревья после Euler tour или на пути после HLD.

### API и сложность

| Метод                     | Смысл                    |  Сложность |
| ------------------------- | ------------------------ | ---------: |
| `new SegmentTree(values)` | построить дерево сумм    |     `O(n)` |
| `set(index,value)`        | присвоить новое значение | `O(log n)` |
| `query(left,right)`       | сумма `[left,right)`     | `O(log n)` |

Память — `O(n)`.

### Как применять

```java
SegmentTree tree = new SegmentTree(a);

long before = tree.query(left, right);
tree.set(index, newValue);
long after = tree.query(left, right);
```

Чтобы переделать шаблон с суммы на минимум, нужно заменить:

```java
tree[parent] = Math.min(tree[leftChild], tree[rightChild]);
```

и использовать `Long.MAX_VALUE` как нейтральный результат отсутствующего
сегмента. Для составной задачи обычно создаётся отдельный `Node` и функция
`merge(Node left, Node right)`.

### Где применялась

- Высшая проба 2023/24 — в официальных решениях встречается
  compressed tree/segment tree;
- Вузовско-академическая олимпиада 2025/26 — segment tree в задачах финала;
- ИОИП 2025/26, «Погоня за патентом» — segment tree среди официальных
  подходов вместе с SPF, Mo и блоками;
- Innopolis Open 2023/24, «Innopolis Data Center» — существенно более
  продвинутый двумерный segment tree вместе с HLD и rerooting.

### Ограничения

- Этот файл не поддерживает массовые изменения диапазона.
- Он хранит только сумму `long`.
- Для range updates нельзя просто вызвать `set` для каждой позиции: получится
  слишком медленно. Нужен lazy propagation.

## LazyMinTree

Файл: [`LazyMinTree.java`](LazyMinTree.java).

### Для чего нужна

Lazy propagation позволяет применить одно изменение сразу ко всему диапазону,
не спускаясь к каждому элементу. Текущий шаблон поддерживает конкретную пару
операций:

- прибавить `delta` ко всем элементам `[left,right)`;
- найти минимум на `[left,right)`.

В массиве `lazy` хранится изменение, которое уже учтено в вершине, но ещё не
передано детям.

### Как распознать

- запросы изменяют целые диапазоны;
- после обновлений нужно получать минимум;
- наивное обновление каждой позиции даёт `O(nq)`;
- изменение одинаково действует на весь полностью покрытый сегмент;
- можно описать, как lazy-тег применяется к узлу и как объединяются дети.

### API и сложность

| Метод                     | Смысл                       |  Сложность |
| ------------------------- | --------------------------- | ---------: |
| `new LazyMinTree(values)` | построить дерево            |     `O(n)` |
| `add(left,right,delta)`   | прибавить на `[left,right)` | `O(log n)` |
| `min(left,right)`         | минимум на `[left,right)`   | `O(log n)` |

Память — `O(n)`. Для запросов нужен непустой исходный массив.

### Как применять

```java
LazyMinTree tree = new LazyMinTree(a);

tree.add(left, right, delta);
long minimum = tree.min(queryLeft, queryRight);
```

Порядок вызова может быть любым: дерево корректно чередует обновления и
запросы.

### Где применялась

- inf-open 2023/24, «Опять запросы» — lazy segment tree;
- диапазонные структуры и lazy-подходы также входят в финальный уровень
  Высшей пробы и ИОИП исследованных сезонов.

Важно: олимпиадная задача подтверждает необходимость **семейства lazy segment
tree**, но её точные операции могут отличаться от `range add + range min`.

### Ограничения

- Этот шаблон не делает присвоение на диапазоне и не хранит сумму.
- Для `range assign`, комбинации assign+add или составного `Node` нужно менять
  тип и композицию lazy-тегов.
- Ошибка чаще всего находится не в рекурсии, а в неверном порядке
  `apply/push/pull`.

## SparseTableMin

Файл: [`SparseTableMin.java`](SparseTableMin.java).

### Для чего нужна

Sparse table заранее вычисляет ответы для отрезков длины `2^k`. Для
идемпотентной операции два перекрывающихся блока можно объединить без двойного
учёта.

Текущий шаблон отвечает на минимум статического массива:

- подготовка `O(n log n)`;
- каждый запрос минимума `O(1)`;
- никаких изменений после построения.

Другие стандартные операции: `max` и `gcd`.

### Как распознать

- массив не меняется;
- запросов очень много;
- нужна идемпотентная операция: `min(x,x)=x`;
- после suffix array нужен RMQ по массиву LCP;
- нужен минимум/максимум на отрезке быстрее `O(log n)`.

Для обычной суммы sparse table в таком виде не подходит: перекрывающиеся
блоки посчитают элементы дважды. Статические суммы решаются prefix sums.

### API и сложность

| Метод                        | Смысл                            |    Сложность |
| ---------------------------- | -------------------------------- | -----------: |
| `new SparseTableMin(values)` | построить таблицу                | `O(n log n)` |
| `min(left,right)`            | минимум непустого `[left,right)` |       `O(1)` |

Память — `O(n log n)`. Массив и каждый запрашиваемый диапазон должны быть
непустыми.

### Как применять

```java
SparseTableMin table = new SparseTableMin(a);

long minimum = table.min(left, right); // left < right
```

Чтобы хранить `max`, достаточно заменить оба `Math.min` на `Math.max`.
Для `gcd` используется функция `gcd` при построении и запросе.

### Где применялась

- Всесибирская олимпиада 2024/25, задача о бухгалтерии — связка
  LCP DP/suffix array/sparse table/Z;
- Вузовско-академическая олимпиада 2024/25 — максимум на диапазоне с
  segment/sparse-подходом.

### Ограничения

- После любого изменения исходного массива таблицу пришлось бы строить заново.
- Для динамических данных нужен Fenwick или segment tree.
- Для неидемпотентной операции требуется disjoint sparse table либо другая
  структура.

## Как выбрать между похожими структурами

### Fenwick или SegmentTree

Выбирать Fenwick, если нужны точечные прибавления и суммы: он короче, обычно
быстрее и потребляет меньше памяти. Выбирать segment tree, если агрегат сложнее
суммы, нужно присваивание, поиск по дереву или дальнейшее расширение до lazy.

### SegmentTree или LazyMinTree

Обычного `SegmentTree` достаточно для точечных изменений. Если один запрос
меняет весь диапазон, нужен lazy-вариант с подходящей композицией тегов.

### SparseTableMin или SegmentTree

Для полностью статического `min/max/gcd` sparse table даёт `O(1)` на запрос.
При любых обновлениях использовать segment tree.

### DSU или RollbackDSU

Обычная DSU быстрее и проще, когда связи только добавляются. Rollback DSU
нужна только при возврате к прошлым состояниям; использовать её «на всякий
случай» не стоит.

## Java-правила для олимпиады

1. Использовать версию Java, указанную в тестирующей системе; этот набор
   проверяется на Java 17.
2. Для сумм, расстояний, произведений и модульной арифметики по умолчанию брать
   `long`. До умножения приводить хотя бы один операнд к `long`.
3. Не использовать `Scanner`, Stream API и создание объектов в самом горячем
   цикле.
4. На графах до `2·10^5` вершин предпочитать итеративные обходы: стандартный
   стек Java легко переполнить рекурсией.
5. В `PriorityQueue` не пытаться уменьшать ключ существующего объекта:
   добавлять новое состояние и пропускать устаревшие при извлечении.
6. У `HashMap`/`HashSet` учитывать boxing и память. Когда ключи лежат в
   небольшом диапазоне, массив почти всегда быстрее и надёжнее.
7. В геометрии проверять возможность переполнения `long`: при больших
   координатах нужен `BigInteger` либо аккуратное сравнение без прямого
   произведения.
8. Перед отправкой проверить пустые диапазоны, индексацию 0/1, `n = 1`,
   отрицательный остаток и границы `INF + weight`.
